Bahkan programmer senior sekalipun tidak menghafal sintaks. Yang paling penting adalah memahami alurnya (yang mana kamu sudah mulai paham) dan tahu di mana harus mencari saat terjadi masalah.

Mengerti fungsi per baris itu bagus untuk proses belajar awal (itulah sebabnya template yang kamu buat penuh komentar), tapi seiring waktu kamu akan lebih sering menggunakan copy-paste lalu memodifikasi (tweaking) sesuai kebutuhan.

Lalu, Bagaimana Cara Belajar Debugging Backend?
Debugging (mencari dan memperbaiki error) adalah skill utama seorang backend developer. Karena di backend tidak ada tampilan visual seperti di frontend, cara kita mencari tahu apa yang salah agak berbeda.

Berikut adalah langkah-langkah dan mentalitas yang bisa kamu latih mulai sekarang:

1. Bertemanlah dengan console.log()
Ini adalah senjata paling ampuh. Saat kodemu tidak berjalan semestinya, jangan langsung menebak-nebak. Lacak jejaknya. Misalnya data tidak masuk ke database saat mencoba fitur Create (POST). Taruh console.log() di beberapa titik:

typescript
static async create(req: Request, res: Response) {
  console.log("1. Berhasil masuk ke Controller Create");
  
  const { nama, alamat, rank } = req.body;
  console.log("2. Data dari frontend:", req.body); // Cek apakah datanya benar-benar terkirim?
  
  try {
     const id = await PlayerModel.create({ nama, alamat, rank });
     console.log("3. Data berhasil disimpan ke database dengan ID:", id);
     // ... res.json(...)
  } catch (error) {
     console.log("4. Terjadi error saat ke Database:", error);
  }
}
Dengan melihat terminal (tempat kamu menjalankan npm run dev), kamu akan langsung tahu di langkah nomor berapa prosesnya terhenti atau gagal.

2. Jangan Panik Melihat Tulisan Merah (Error Log)
Saat server crash atau memunculkan tulisan error panjang di terminal, jangan langsung panik. Baca baris pertama dan cari nama file kamu. Biasanya error memberi tahu persis di mana masalahnya: TypeError: Cannot read properties of undefined (reading 'nama') at PlayerController.create (d:\CODEX\template_ts\src\controllers\playerController.ts:67:23) Artinya: Error ada di playerController.ts baris 67. Masalahnya kamu mencoba membaca variabel nama tapi objeknya kosong/tidak ada.

3. Gunakan Alat Penguji API (Postman / Thunder Client)
Seringkali saat membuat full-stack, kita bingung: "Ini yang salah database-nya, backend-nya, atau frontend-nya yang gagal menampilkan?" Untuk memisahkannya, gunakan extension seperti Thunder Client di VS Code atau aplikasi Postman. Tembak URL http://localhost:3000/api/player langsung dari sana.

Jika dari Thunder Client hasilnya benar (JSON muncul), berarti backend-mu aman, yang error pasti frontend-nya.
Jika dari Thunder Client hasilnya error, berarti masalahnya murni di backend (Controller/Model).
4. Pecah Masalah Menjadi Bagian Kecil (Divide & Conquer)
Jika suatu fitur gagal, cek berurutan seperti alur yang sudah kita bahas:

Apakah URL dan metodenya sudah benar di Routes?
Apakah datanya berhasil diterima di Controller? (Cek dengan console.log)
Apakah perintah SQL-nya sudah benar di Model? (Coba jalankan query SQL-nya langsung di aplikasi seperti phpMyAdmin/DBeaver).
5. Latihan Terbaik: Rusak Kodemu Sendiri! (Eksperimen)
Mumpung ini template buatanmu sendiri, cobalah untuk sengaja merusaknya:

Coba salahkan password database di .env, lalu lihat error apa yang muncul di terminal.
Coba ganti SELECT * FROM player di Model menjadi SELECT * FROM tabel_ngawur, lalu panggil API-nya. Lihat bagaimana catch menangkap pesan error-nya.
Coba hapus blok app.use(express.json()) di server.ts, lalu coba tambah data dari frontend. Apa yang terjadi?
Semakin sering kamu melihat bentuk-bentuk error, kamu akan memiliki "insting" otomatis. "Oh, tulisan errornya begini, pasti masalahnya ada di database nih," atau "Oh, ini pasti lupa nambahin await," dan seterusnya.
